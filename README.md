# Stellar Burgers

Учебное frontend-приложение для создания и оформления бургеров. Пользователь может собирать бургер из доступных ингредиентов, просматривать информацию о них, оформлять заказы, работать с личным профилем и просматривать историю заказов.

## Стек

* React
* TypeScript
* Redux Toolkit
* React Router
* REST API
* Jest
* Playwright
* HAR

## Реализованная функциональность

* Загрузка ингредиентов с сервера и отображение их по категориям.
* Добавление и удаление ингредиентов из конструктора бургера.
* Выбор булки и начинки, изменение состава заказа и автоматический расчёт итоговой стоимости.
* Оформление заказа с передачей выбранных ингредиентов на сервер.
* Отображение номера созданного заказа в модальном окне.
* Лента заказов и просмотр информации об отдельном заказе.
* Регистрация и авторизация пользователей.
* Восстановление пользовательской сессии после перезагрузки страницы.
* Выход из аккаунта.
* Просмотр и редактирование данных профиля.
* Просмотр истории заказов пользователя.
* Защита маршрутов для авторизованных и неавторизованных пользователей.
* Возврат пользователя на исходную страницу после успешной авторизации.
* Навигация с отображением активного раздела.
* Модальные окна ингредиентов и заказов с сохранением фонового маршрута.
* Поддержка прямых ссылок на страницы ингредиентов и заказов.

## Управление состоянием

Глобальное состояние приложения реализовано с помощью Redux Toolkit.

Созданы отдельные слайсы для:

* ингредиентов;
* конструктора бургера;
* заказов;
* авторизации пользователя.

Для взаимодействия с REST API используются асинхронные thunk-экшены. В состоянии учитываются загрузка данных, успешное выполнение запросов и возникающие ошибки.

## Маршрутизация

Маршрутизация реализована с помощью React Router.

Поддерживаются два сценария открытия ингредиентов и заказов:

* при переходе из интерфейса информация открывается в модальном окне поверх текущей страницы;
* при переходе по прямой ссылке открывается отдельная страница.

Для авторизации используются защищённые маршруты, которые ограничивают доступ к профилю и другим пользовательским разделам.

## Тестирование

Для приложения реализованы unit- и E2E-тесты.

### Unit-тесты

С помощью Jest протестированы Redux-редьюсеры:

* начальное состояние;
* обработка обычных actions;
* обработка неизвестного action;
* состояния `pending`, `fulfilled` и `rejected` асинхронных операций.

### E2E-тесты

С помощью Playwright протестированы основные пользовательские сценарии:

* загрузка ингредиентов;
* добавление ингредиентов в конструктор;
* открытие и закрытие модального окна ингредиента;
* сборка бургера;
* проверка авторизации пользователя;
* передача токена авторизации в запросах;
* оформление заказа;
* открытие модального окна с номером созданного заказа;
* очистка конструктора после успешного оформления заказа;
* закрытие модального окна заказа.

Для изоляции E2E-тестов от реального backend используются HAR-файлы. Сетевые запросы к API перехватываются через `page.routeFromHAR`, что позволяет воспроизводить заранее записанные ответы сервера и получать стабильные результаты тестирования.
